# Compact donor practice cards

Load only the card for the selected dynamic role. These are short local fallbacks, not claims that a donor skill was invoked. External host skills take priority when the exact skill is installed and callable. Full attributed snapshots under `vendor/` are read only for substantial stages; otherwise these cards keep token use low.

| Capability | Compact practice card | Candidate exact skills |
|---|---|---|
| **Architecture / DDD** | Identify domain language and invariants, draw boundaries, trace one use case across modules, compare the simplest alternatives, record reversible decision + trigger to revisit. | `dddsoftware-architecture`, `project-planner` |
| **Research / academic** | Turn the question into claims; search primary sources first; record date, method, limitation and disagreement; separate source fact from inference; stop when marginal sources repeat the same evidence. | `deep-research`, `deep-research-pro`, `academic-researcher` |
| **Fact checking** | Atomize each consequential claim; find independent primary evidence and strongest counterevidence; label confirmed/supported/tentative/conflicted/unknown. | `fact-checker` |
| **Product discovery** | Clarify who has the problem and what they do now; list riskiest assumptions; define observable success; run the cheapest reversible experiment before scaling the design. | `product-test`, `product-tester`, `project-planner` |
| **Product QA** | Derive risk-based acceptance examples; include regression and negative cases; test user-visible behavior rather than implementation shape; report PASS/FAIL/NOT_RUN honestly. | `product-test`, `product-tester`, `webapp-testing`, `gate` |
| **Offensive security** | Establish authorized scope; think attacker-first; map trust boundaries; trace foothold→primitive→control bypass→impact; validate minimum PoC; keep only evidenced attack-chain edges. See `offensive_security.md`. | `security-audit`, `vibe-security-audit`, selected `Anthropic-Cybersecurity-Skills` |
| **UI/UX and design systems** | Inspect actual UI and task; define user/job and design direction; test states, hierarchy, responsive reflow, accessibility and consistency; validate rendered results, not just source. | `frontend-design`, `ux-ui-icon-agent`, `design-review`, `design-screen`, `web-component-design`, `mui` |
| **Accessibility** | Check semantic names/roles, keyboard order/focus, contrast, reduced motion, zoom/reflow and error messages; tie each finding to an observed criterion and location. | `a11y-audit`, `design-qa`, `antislop-human`, `antislop-layoutmobile` |
| **Data and visualization** | Check provenance/schema/missingness and denominator; validate transformations; choose a chart for comparison/distribution/time/relationship; disclose uncertainty and avoid causal overclaim. | `data-analyst`, `visualization-expert`, `data-dashboard` |
| **Prompt/harness** | Define trigger, inputs, trusted vs untrusted data, tool grants, output schema, failure/uncertainty behavior and adversarial regression prompts. | `prompt-engineer`, `skill-conductor`, `mcp-builder` |
| **Documents** | Inspect source artifact and requested output; preserve facts and structure; render/export if tools allow; verify pages/sheets/slides and report unrendered checks. | `docx`, `pdf`, `xlsx`, `pptx`, `oil-ppt` |
| **README/docs** | Lead with purpose and audience; give one validated setup path and working example; state limits; test relative links and commands. | `beautify-github-readme`, `doc-coauthoring` |
| **Icons/visual assets** | Start from use case, size, style and background; create coherent set; inspect transparency, cropping and actual-scale legibility; preserve source/provenance. | `oil-icon`, `logo-design`, `canvas-design` |
| **Framework implementation** | Confirm the repository's language/framework and version before selecting detailed advice; find existing conventions and tests; make one narrow change and run the closest check. | `python-pro`, `cpp-pro`, `csharp-developer`, `dotnet-core-expert`, `react-expert`, `nextjs-developer`, `react-dev` |
| **MCP/tools** | Specify one action per tool; validate inputs; bound authority and data exposure; return structured errors; test denial, timeout and malformed responses. | `mcp-builder`, `mcp-server-fixed` |
| **Slides / visual reports** | Define audience, claim and narrative; one message per slide; evidence source beside chart; render and inspect slide images; distinguish verified asset from mock. | `oil-ppt`, `pptx`, `theme-factory`, `visualization-expert` |
| **Game modding** | Confirm game/build/mod API and ownership; inspect compatibility; isolate files; backup saves; test locally/offline; document rollback. | `mod-any-game`, `game-recon`, `asset-pipeline`, `game-automation`, `reverse-engineering` |
| **Anti-slop UI & Code** | Убирать типовые маркеры ИИ-генерации (случайные градиенты, бессмысленные тени, одинаковые карточки); делать дизайн сдержанным и функциональным; проверять WCAG контраст и мобильный рефлоу. | `antislop`, `antislop-ui`, `antislop-code`, `antislop-human`, `antislop-layoutmobile` |
| **Anti-slop Copywriting** | Исключать водянистые штампы («game-changing», «unlock the power», «погрузитесь в мир»); писать прямо, емко, сохранять факты, формулировать пользу для читателя. | `antislop-copywriting`, `doc-coauthoring`, `ux-writing`, `internal-comms` |
| **Design tokens & Figma** | 3-уровневая архитектура токенов (primitive → semantic → component DTCG); синхронизация с Figma Variables; экспорт в CSS variables и Tailwind. | `design-tokens`, `brandkit`, `figma-integration`, `migrate-design-system` |
| **Theme & Web artifacts** | Назначение темы и цветовой палитры без визуального шума; изолированные HTML/SVG/React-песочницы с интерактивным состоянием. | `theme-factory`, `web-artifacts-builder`, `canvas-design` |
| **Deep Cybersecurity tactics** | Активный аудит IAM, эскалация привилегий в Active Directory, анализ смарт-контрактов, обратная разработка бинарников, анализ дампов памяти. Строго для санкционированных тестов. | Семейства `Anthropic-Cybersecurity-Skills-1.3.0` |

| **Parity Testing & Porting** | Потиковая верификация против оригинального бинарника (оракула). Фиксированный сид, потиковый трейс полей, сравнительный гейт до слияния. Исключать недетерминизм. | `game-parity-port` |
| **Session Handoff & Memory** | Создание структурированного handoff-документа при исчерпании контекста (цели, проверенные факты, блокеры, следующий шаг) для бесшовной передачи следующему агенту. | `session-handoff`, `claude-code-sessions` |
| **Enterprise ISMS & Compliance** | Проверка соответствия ISO 27001, GDPR, HIPAA, ведение матриц рисков, аудит журналов доступа и разделения обязанностей (SoD). | `isms-audit-expert`, `data-privacy-compliance`, `gdpr-dsgvo-expert` |
| **Parallel Agent Dispatch** | Разделение независимых подсистем/сбоев по изолированным субагентам без общего разделяемого мутабельного состояния с последующей консолидацией. | `dispatching-parallel-agents`, `multi-agent-coordinator` |
| **Database Architecture & Migration** | Проектирование реляционных/NoSQL схем, бессбойные миграции (expand-contract), индексы, изоляция транзакций и оптимизация пула соединений. | `database-architect`, `database-migration`, `postgres-schema-design`, `sql-pro` |
| **Cloud Native & Containers** | Многоэтапная сборка Docker (distroless/scratch), аудит безопасности контейнеров, Kubernetes RBAC и декларативные GitOps пайплайны. | `docker-expert`, `kubernetes-architect`, `gitops-workflow` |

If the host has the exact skill callable, pass it a minimal scope packet and let it own that stage once. If it is merely discoverable on disk, inspect its name, source, license and trigger before claiming use. Never install a skill silently. If the donor asset is not license-cleared, use this independent compact method rather than copying its files.
